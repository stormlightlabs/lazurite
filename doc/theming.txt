*theming.txt*              Theming (Material + Theme Packs + User Customization)

================================================================================
Design Principles + Success Criteria                          *theme-principles*
================================================================================

Outcome:
- The app looks "correct" (hierarchy, emphasis, states) while preserving your
  Oxocarbon vibe.
- Users can pick built-in themes (Oxocarbon, Catppuccin, Nord, Rosé Pine,
  Atom/One Dark) with light/dark variants, and optionally customize.

Success criteria:
- Squint test: cards/posts/chips/nav remain visually separable without relying
  on text.
- Contrast: text and chip labels meet platform expectations; at minimum chips
  follow spec role usage.
- Theme packs are swappable instantly; selection persists.

================================================================================
Roadmap                                                          *theme-roadmap*
================================================================================
3. Theme controller + persistence + runtime switching                  *theme-3*

Goal:
- User can switch theme packs + variant (light/dark) at runtime with persisted
  selection.

Current state:
- ThemeModeController exists but only toggles light/dark mode (no pack selection)
- No persistence layer

Tasks:
- [ ] Extend ThemeController (Riverpod) with:
      - currentThemePackId: String
      - currentVariantId: String?
      - setThemePack(packId, [variantId]): switches active pack/variant
      - getActiveThemeData(): ThemeData (via ThemeFactory)
      - optional: dynamicColorEnabled for Android 12+ Material You
- [ ] Add persistence:
      - Drift table to keep settings in the central DB
      - Store: current pack ID, current variant ID (or brightness preference)
- [ ] Wire MaterialApp(theme, darkTheme, themeMode) from controller
- [ ] Migrate existing ThemeModeController to new ThemeController

Deliverables:
- Theme pack + variant switch updates UI without restart
- Selection persists across app restarts
- System brightness preference ("auto") supported

--------------------------------------------------------------------------------
4. Theme Picker UI                                                     *theme-4*

Goal:
- User can browse, preview, and select theme packs from settings.

Current state:
- No settings UI for theme selection
- No preview widgets

Design:
- Settings → Appearance page
  - Theme pack list/dropdown (shows all available packs)
  - Variant selector: System / Light / Dark / (pack-specific variants)
  - Live preview cards showing Home feed, Post card, Chip row, Nav bar
- Desktop enhancements (optional):
  - Split pane theme inspector showing multiple components
  - Computed role display (surfaceContainerLow, outlineVariant values)

Tasks:
- [ ] Create AppearancePage (Settings section)
      - Pack selector widget (list or dropdown)
      - Variant selector (segmented control or radio buttons)
      - Wire to ThemeController
- [ ] Build preview widgets:
      - ThemePreviewCard: mini Home feed + nav bar rendering
      - Shows visual hierarchy at a glance
- [ ] Add "Export theme JSON" button (prepare for T6 import/export)
- [ ] Optional: Desktop-only ThemeInspectorPane with role inspector

Deliverables:
- User can see theme differences before applying
- Mobile flow: 2-3 taps to switch theme
- Desktop: richer preview pane with computed role details

5. Built-in theme packs                                                *theme-5*

Goal:
- Ship curated theme packs with light/dark variants.

Current state:
- Only Oxocarbon pack exists (light + dark variants in
  lib/src/app/theming/packs/oxocarbon_theme_pack.dart)
- No Catppuccin, Nord, Rosé Pine, or One Dark packs

Theme sources:
- Catppuccin: 4 flavors (Latte/Frappé/Macchiato/Mocha) with documented palettes
- Nord: documented palette for UI contexts
- Rosé Pine: base/surface roles + variants (main/moon/dawn)
- One Dark: canonical hex values from Atom editor

Tasks:
- [ ] Define ThemePacks for each (Dart constants or JSON):
      - catppuccin: latte (light), frappé/macchiato/mocha (dark variants)
      - nord: light + dark variant
      - rose-pine: dawn (light), main/moon (dark)
      - one-dark + one-light
- [ ] Map each palette → M3 roles:
      - base/background → surfaceDim/surface
      - panel/card → surfaceContainerLow/Default/High
      - borders → outlineVariant/outline
      - text → onSurface/onSurfaceVariant
      - accent(s) → primary/secondary/tertiary (+ containers)
- [ ] Apply accent strategy per theme type:
      - High-contrast (oxocarbon, one-dark): vivid primary
      - Pastel (catppuccin, rose-pine, nord): restrained accents, use
        secondary for chips, tertiary for highlights
- [ ] Extend role lint tests for all new packs

Deliverables:
- All packs ship with both brightness variants (where applicable)
- Each pack passes role lint tests and maintains visual hierarchy
- Export all packs from lib/src/app/theming/theming.dart

--------------------------------------------------------------------------------
6. Customizable themes (user edits + import/export)                   *theme-6*

Goal:
- Allow users to tune themes without breaking visual consistency.

Scope (v1):
- Let users adjust:
  - primary/secondary/tertiary
  - surface + surfaceContainerLow/High
  - outlineVariant
  - typography scale (small/normal/large)
- Keep everything else derived to protect role system integrity

Tasks:
- [ ] Add CustomThemeDraft model persisted in DB/prefs
      - Based on a base pack with role overrides
      - Validated on load (fallback to base pack if invalid)
- [ ] Editor UI:
      - Color pickers or brightness/tone sliders for adjustable roles
      - Live preview (reuse ThemePreviewCard from T4)
      - Reset-to-pack defaults button
- [ ] Export/Import JSON:
      - Schema: { id, basePack, roleOverrides, typography }
      - Validate on import and reject/warn if roles are missing or conflicting
      - Allow sharing custom themes as JSON files

Deliverables:
- Users can create custom variants without flattening hierarchy
- Custom themes are validated and safe
- Export/import enables theme sharing

--------------------------------------------------------------------------------
7. Quality gates: expanded role linting + accessibility               *theme-7*

Goal:
- Ensure all theme packs (built-in + custom) maintain M3 role integrity and
  accessibility standards.

Current state:
- Role lint tests exist (test/src/app/theming/theme_role_lint_test.dart)
- Validates required roles, hierarchy integrity, container ladder ordering
- Only covers Oxocarbon pack

Tasks:
- [ ] Extend role lint tests for all packs (automated with pack registry)
- [ ] Add accessibility checks:
      - Contrast ratio tests (WCAG AA minimum for onSurface/onSurfaceVariant)
      - Ensure primary/secondary accents meet contrast requirements
- [ ] Golden tests (optional):
      - Visual regression tests for Home screen, Post card, Chip row, Nav bar
      - Compare against baseline screenshots per pack
- [ ] Pre-release validation:
      - CI step runs all role lint + accessibility tests
      - Fails build if any pack violates constraints

Deliverables:
- Adding a new pack is safe: drop in palette → mapping → tests pass
- Visual regressions and accessibility issues caught before release
- Confidence that all packs maintain design principles
