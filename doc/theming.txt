*theming.txt*              Theming (Material + Theme Packs + User Customization)

==============================================================================
T. Theming 2.0 (why we’re changing it)                               *theme-T*
==============================================================================

- Many Material 3 components rely on the broader set of tone-based
  surfaces/containers and "onSurfaceVariant/outlineVariant" emphasis roles.
- Material 3 is explicitly designed around *color roles* applied consistently
  across UI.
- Flutter has been expanding Material 3 ColorScheme roles (tone surfaces +
  containers, and more accent roles), and some older roles are deprecated (e.g.,
  background/onBackground, surfaceVariant).

Outcome:
- The app looks "correct" (hierarchy, emphasis, states) while preserving your
  Oxocarbon vibe.
- Users can pick built-in themes (Oxocarbon, Catppuccin, Nord, Rosé Pine,
  Atom/One Dark) with light/dark variants, and optionally customize.

================================================================================
0. Design principles + success criteria                               *theme-T0*
================================================================================

Principles (Material 3):
- Use semantic color roles (surface containers, outlineVariant,
  onSurfaceVariant) rather than raw hex values sprinkled through widgets.
- Create hierarchy with tone-based surfaces/containers rather than heavy
  dividers.
- Navigation components must have a clear active indicator (selected state).
- Chips have specific color roles in spec (filter chip uses onSurfaceVariant +
  outline and optionally surfaceContainerLow).

Success criteria:
- Squint test: cards/posts/chips/nav remain visually separable without relying
  on text.
- Contrast: text and chip labels meet platform expectations; at minimum chips
  follow spec role usage.
- Theme packs are swappable instantly; selection persists.

1. Refactor theme into role-first "ThemeSpec"                          *theme-1*
================================================================================

Goal:
- Replace "AppColors + ThemeData" with a data-driven theme system that maps each
  palette to Material 3 ColorScheme roles.

Tasks:
- [x] Create domain types:
      - ThemePack(id, name, author, variants[])
      - ThemeVariant(id, brightness, palette, derivedScheme)
      - ThemeSpec(seed?, surfaces?, accents?, typography?, shapes?)
- [x] Build ColorScheme by roles (NOT by arbitrary hex):
      - Provide full set of M3 surfaces/containers where available:
        surfaceDim/bright + surfaceContainerLowest/Low/Default/High/Highest
      - Provide outline + outlineVariant, onSurfaceVariant
      (These roles are core to M3’s "tone-based surfaces" model.)
- [x] Implement ThemeFactory.buildThemeData(ThemeVariant):
      - ThemeData(useMaterial3: true, colorScheme: ...)
      - Centralize component themes (NavBar, Chips, Cards, ListTiles, Dividers,
        Inputs)

Deliverables:
- A single file/function constructs ThemeData for *any* theme pack variant.
- No widget outside the theme layer uses hard-coded palette colors.

================================================================================
2. Component theming                                                   *theme-2*
================================================================================

Navigation (bottom):
- [x] Theme NavigationBar to match M3 guidance:
      - active indicator is a container color role (NOT primary tint overlay)
      - selected/unselected icon/label colors align with
        onSurface/onSurfaceVariant
  M3 nav bar uses an active indicator and clear active state.

Chips (feed selector row):
- [x] Convert "feed pills" to FilterChips and theme them per spec:
      - unselected: outline + onSurfaceVariant
      - selected: container role + onContainer
  M3 chip spec explicitly calls out these roles.

Cards (posts + embeds):
- [ ] Move post rows to Card/Surface using surfaceContainerLow
      (or surfaceContainer)
- [ ] Give embeds a slightly higher container role than the parent post container
      ("contained area against surface" guidance).

Dividers and outlines:
- [ ] Default dividers should use outlineVariant (subtle), not strong contrast
      lines.
- [ ] Reserve outline for boundaries that truly need emphasis.

Text emphasis:
- [ ] Ensure secondary metadata (handle, timestamp) uses onSurfaceVariant.
- [ ] Keep body text on onSurface (highest legibility).

Inputs / dialogs / sheets:
- [ ] TextField, Dialog, BottomSheet should use container roles and consistent
      scrims.

Deliverables:
- Home timeline screen reads with clear hierarchy:
  background < cards < embeds < selected chip/nav.

Tasks:

      - optional dynamicColorEnabled (Android 12+)
- [ ] Persist selection:
      - lightweight: shared_preferences

  Flutter theming pattern is to supply ThemeData through MaterialApp.

Deliverables:
- Theme switch updates UI without restart.
- Theme selection is remembered.

5. Built-in theme "packs"                                              *theme-5*
================================================================================

Goal:
- Ship a curated set with light/dark variants.

Theme sources:
- Catppuccin has 4 "flavors" (Latte/Frappé/Macchiato/Mocha) with defined
  palettes.
- Nord documents its palette and intended usage across UI contexts.
- Rosé Pine defines base/surface roles and variants (main/moon/dawn).
- One Dark provides canonical hex values used widely.

Tasks:
- [ ] Define ThemePack JSON (or Dart constants) for each:
      - oxocarbon_dark + oxocarbon_light (yours, refined into roles)
      - catppuccin: latte (light), frappe/macchiato/mocha (dark variants)
      - nord: light + dark variant mapping (or one pack w/ both)
      - rose-pine: dawn (light), main/moon (dark)
      - one-dark + one-light (atom)
- [ ] For each pack, map palette → roles:
      - base/background → surfaceDim/surface
      - panel/card → surfaceContainerLow/Default/High
      - borders → outlineVariant/outline
      - text → onSurface/onSurfaceVariant
      - accent(s) → primary/secondary/tertiary (+ containers)
- [ ] Provide per-pack "accent strategy":
      - high-contrast themes (oxocarbon/one-dark) can use vivid primary
      - pastel themes (catppuccin/rose-pine/nord) should keep accents
        restrained, use secondary for chips and tertiary for highlights
        (Material guidance on roles).

Deliverables:
- All packs ship with both brightness variants (where applicable).
- Each pack passes golden tests and doesn’t break component contrast.

================================================================================
6. Customizable themes (user edits + import/export)                    *theme-6*
================================================================================

Goal:
- Allow users to tune themes without turning your app into an untestable mess.

Opinionated customization scope (v1):
- Let users adjust:
  - primary/secondary/tertiary
  - surface + surfaceContainerLow/High
  - outlineVariant
  - typography scale (small/normal/large)
- Keep everything else derived to protect visual consistency (role system).

Tasks:
- [ ] Add CustomThemeDraft model persisted in DB/prefs
- [ ] Editor UI:
      - sliders for brightness/tone (or color pickers)
      - live preview (same as T4)
      - reset-to-pack defaults
- [ ] Export/Import:
      - JSON schema: ThemeSpec { id, base palette, role overrides }
      - validate on import and fall back safely

Deliverables:
- Users can create a custom variant without breaking the app’s hierarchy.

================================================================================
7. Quality gates: tests + role linting + accessibility checks          *theme-7*
================================================================================

Tasks:
- [ ] "Role lint" checks (unit tests) for ThemeVariant:
      - required roles present (surface containers, onSurfaceVariant,
        outlineVariant)
      - no role equals another in ways that flatten hierarchy
        (e.g., surface == surfaceContainerLow)

Deliverables:
- Adding a new theme pack is safe: drop in palette → mapping → tests.
- Visual regressions are caught before release.

Implementation notes (based on your current theme.dart)            *theme-notes*
================================================================================

Current file highlights to address:
- We only set surface + surfaceContainerHighest; introduce the full
  surfaceContainer ladder so posts/embeds can sit on different planes.
- NavigationBar indicator uses primary alpha; shift to container roles for
  "active indicator" semantics.
- CardTheme elevation=0 is fine if we lean on container roles; otherwise
  everything flattens. Use surfaceContainerLow/Default and keep elevation
  minimal.
