*theming.txt*              Theming (Material + Theme Packs + User Customization)

================================================================================
Design Principles + Success Criteria                          *theme-principles*
================================================================================

Outcome:
- The app looks "correct" (hierarchy, emphasis, states) while preserving your
  Oxocarbon vibe.
- Users can pick built-in themes (Oxocarbon, Catppuccin, Nord, Rosé Pine,
  Atom/One Dark) with light/dark variants, and customize.

Success criteria:
- Squint test: cards/posts/chips/nav remain visually separable without relying
  on text.
- Contrast: text and chip labels meet platform expectations; at minimum chips
  follow spec role usage.
- Theme packs are swappable instantly; selection persists.

================================================================================

================================================================================
3. Theme controller + persistence + runtime switching                  *theme-3*

Goal:
- User can switch theme packs + variant (light/dark) at runtime with persisted
  selection.

Tasks:
- [x] Extend/Create ThemeController (Riverpod) with:
      - currentThemePackId: String
      - currentVariantId: String?
      - setThemePack(packId, [variantId]): switches active pack/variant
      - getActiveThemeData(): ThemeData (via ThemeFactory)
- [x] Add persistence:
      - Drift table to keep settings in the central DB
      - Store: current pack ID, current variant ID (or brightness preference)
- [x] Wire MaterialApp(theme, darkTheme, themeMode) from controller
- [x] Migrate existing ThemeModeController to new ThemeController
- [ ] Add dynamicColorEnabled for Android 12+ Material You

Deliverables:
- Theme pack + variant switch updates UI without restart
- Selection persists across app restarts
- System brightness preference ("auto") supported

Design:

  - Variant selector: System / Light / Dark / (pack-specific variants)

      - Wire to ThemeController

5. Built-in theme packs                                                *theme-5*

Goal:
- Ship curated theme packs with light/dark variants.

Theme sources:
- Catppuccin: 4 flavors (Latte/Frappé/Macchiato/Mocha) with documented palettes
- Nord: documented palette for UI contexts
- Rosé Pine: base/surface roles + variants (main/moon/dawn)
- One Dark: canonical hex values from Atom editor

Tasks:
- [x] Define ThemePacks for each (Dart constants):
      - catppuccin: latte (light), frappé/macchiato/mocha (dark variants)
      - nord: light + dark variant
      - rose-pine: dawn (light), main/moon (dark)
      - one-dark + one-light
- [x] Map each palette → M3 roles:
      - base/background → surfaceDim/surface
      - panel/card → surfaceContainerLow/Default/High
      - borders → outlineVariant/outline
      - text → onSurface/onSurfaceVariant
      - accent(s) → primary/secondary/tertiary (+ containers)
- [x] Apply accent strategy per theme type:
      - High-contrast (oxocarbon, one-dark): vivid primary
      - Pastel (catppuccin, rose-pine, nord): restrained accents, use
        secondary for chips, tertiary for highlights
- [x] Extend role lint tests for all new packs

Deliverables:
- All packs ship with both brightness variants (where applicable)
- Each pack passes role lint tests and maintains visual hierarchy
- Export all packs from lib/src/app/theming/theming.dart

--------------------------------------------------------------------------------
6. Customizable themes (user edits + import/export)                   *theme-6*

Goal:
- Allow users to tune themes without breaking visual consistency.

Scope:
- Let users adjust:
  - primary/secondary/tertiary
  - surface + surfaceContainerLow/High
  - outlineVariant
  - typography scale (small/normal/large)
- Keep everything else derived to protect role system integrity

Tasks:
- [x] Add CustomThemeDraft model persisted in DB/prefs
      - Based on a base pack with role overrides
      - Validated on load (fallback to base pack if invalid)
- [x] Editor UI:
      - Color pickers or brightness/tone sliders for adjustable roles
      - Live preview (reuse ThemePreviewCard from T4)
      - Reset-to-pack defaults button
- [x] Export/Import JSON:
      - Schema: { id, basePack, roleOverrides, typography }
      - Validate on import and reject/warn if roles are missing or conflicting
      - Allow sharing custom themes as JSON files

Deliverables:
- Users can create custom variants without flattening hierarchy
- Custom themes are validated and safe
- Export/import enables theme sharing

--------------------------------------------------------------------------------
7. Animation system (Material 3 motion + accessibility)                *theme-7*

Goal:
- Implement Material Design 3 motion patterns with comprehensive accessibility
  controls for motion-sensitive users.

Design:
- Material Design 3 transitions (container transform, shared axis, fade through)
- AnimationController service (Riverpod) with mode + speed controls
- Accessibility settings: full/reduced/minimal/system animation modes
- Speed multiplier adjustment (0.5x to 2.0x)
- Respect platform accessibility (disableAnimations, reduceMotion)

Tasks:
- [x] Add animations package dependency
- [x] Create AnimationController service with Riverpod
      - Animation mode enum: full/reduced/minimal/system
      - Speed multiplier setting
      - Helper methods for duration calculation and mode resolution
- [x] Add Drift table for animation preferences persistence
- [x] Build Settings → Accessibility page for animation controls
      - Mode selector (full/reduced/minimal/system)
      - Speed multiplier slider with preview
      - Wire to AnimationController
- [ ] Implement core navigation transitions
      - Home feed scroll animations
      - Post detail expansion (container transform)
      - Tab navigation (shared axis)
      - Composer screen transitions
- [ ] Add secondary polish animations
      - List item entrance
      - Pull-to-refresh
      - Loading states
      - Button feedback

Deliverables:
- Material Design 3 motion patterns applied consistently
- Users can control animation intensity from settings
- Platform accessibility settings (reduce motion, disable animations) respected
- Animations perform at 60 FPS on target devices
- No loss of functionality when animations disabled
- Animation preferences persist across restarts
