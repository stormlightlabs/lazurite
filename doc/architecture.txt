*bsky_client_roadmap.vim* - Flutter (Dart) Bluesky client

================================================================================
Host routing model (detailed implementation notes)                *bsky-host*
================================================================================

Read-after-write smoothing:
* PDS can patch AppView reads for consistency

Implementation:

* Two Dio instances:
  * `dioPublic`  baseUrl = https://public.api.bsky.app
  * `dioPds`     baseUrl = user's PDS URL (resolved via identity)
* Never "guess" where to send a call at runtime; encode it in an endpoint map.

================================================================================
3. Identity resolution + session bootstrap                         *bsky-ident*
================================================================================

Implementation guidance:

* Prefer DID + at:// URIs internally; handles are user-facing and less stable.
* Handle→DID→PDS resolution needed for login and normalizing cache keys

================================================================================
4. Write endpoint implementation notes                             *bsky-write*
================================================================================

uploadBlob constraints:

* Blobs are "temporary" until referenced by a record (time window).
* All repo writes go to the user's PDS.

================================================================================
5. DM service proxy implementation                                   *bsky-dms*
================================================================================

Service proxy header (XRPC spec):

* Header name: `atproto-proxy`
* Value format: `did#serviceId`
* For Bluesky chat: `did:web:api.bsky.chat#bsky_chat`

Dio implementation pattern:

* Add an interceptor on `dioPds` for "chat.*" calls:
  * set `atproto-proxy: did:web:api.bsky.chat#bsky_chat`
  * include auth headers (OAuth bearer + whatever your auth layer requires)

Practical warning:

* If you call chat endpoints against public.api.bsky.app you will get
  404/unsupported; you must proxy via PDS with `atproto-proxy`.

================================================================================
6. Smart folder implementation strategy                            *bsky-folders*
================================================================================

Folder rule types (suggested MVP):

* Author allow/deny (DID list)
* Keyword include/exclude (post text)
* Has media / has link
* Replies only / exclude replies
* Bookmarked only
* "Unread only" (local read-state)

Execution strategy (opinionated):

* Start non-materialized:
  * SELECT posts WHERE <rules> ORDER BY indexedAt DESC LIMIT/OFFSET (or keyset)
* Upgrade to materialized if needed:
  * On cache insert, evaluate rules and populate local_folder_items

================================================================================
7. Draft publish pipeline                                           *bsky-drafts*
================================================================================

Pipeline (when user hits "Post"):

1. If draft has media files not yet uploaded → uploadBlob
2. Construct app.bsky.feed.post record with blob references
3. createRecord (collection app.bsky.feed.post)
4. On success: mark draft as published (or delete)
