*dev-tools.txt*                                                 ATProto DevTools
================================================================================

References:
- .sandbox/spec_debug_devtools_2026_01_08.md - Complete technical specification
- doc/roadmap.txt section M.5 - High-level milestone breakdown and tasks

Two distinct features:
1. Internal Debug Mode (kDebugMode only) - For developers during development
2. User-Facing DevTools (production)

================================================================================
DevTools - Scope & safety boundaries                                 *dev-scope*
================================================================================

Internal Debug Mode (kDebugMode only):
- Debug overlay with system info, network inspector, performance metrics
- Only available in Flutter debug builds (kDebugMode)
- Never show or export auth secrets (tokens/DPoP keys)

User-Facing DevTools (production builds):
- Repository inspection and exploration
- Available in both debug and release builds
- Settings → "Developer Tools" toggle (default off for new users)
- Read-only by default: view your own repo + optionally other public repos
- Write mode triple-gated: Settings toggle + biometric auth + per-action confirmation

Hard rules (both modes):
- Never show or export auth secrets (tokens/DPoP keys) stored in secure storage
- Default to "My DID". "Other DID" requires explicit toggle and confirmation
- Record JSON rendering must be robust to hostile/weird shapes (defensive UI)

Host routing:

- These are PDS repo endpoints; call the user's PDS directly:
  - describeRepo / listRecords / getRecord.
    (Do NOT use `atproto-proxy` header; that header is for proxying to other
    services, e.g. labelers/chat.)

================================================================================
DevTools - Data + endpoints (canonical)                                *dev-api*
================================================================================

Repo introspection:

- com.atproto.repo.describeRepo (GET) - lists collections for a repo.
  Query: repo=<did|handle>

Collection listing:

- com.atproto.repo.listRecords (GET) - list records in a collection.
  Query: repo=<did|handle>
         collection=<nsid>
         limit=<n>
         cursor=<cursor?>
         rkeyStart/rkeyEnd?
         reverse?

Single record:
- com.atproto.repo.getRecord (GET) - fetch record by repo+collection+rkey.
  Query: repo=<did|handle>
         collection=<nsid>
         rkey=<rkey>
         cid?<optional>

Advanced proof (optional later):
- com.atproto.sync.getRecord (GET) - "prove existence/non-existence" blocks.

Mutation:
- com.atproto.repo.createRecord (POST)
- com.atproto.repo.putRecord (POST)
- com.atproto.repo.deleteRecord (POST)
- com.atproto.repo.applyWrites (POST; batched transaction)

================================================================================
DevTools - UX: desktop vs mobile                                        *dev-ux*
================================================================================

Desktop (high visibility / inspector):
- 3-pane layout:
  - Left: Collections (search + pinned)
  - Middle: Record list (paged, sortable, filterable)
  - Right: Record inspector (JSON tree + metadata + actions)

Mobile (usable drill-down):
- Screen stack:
  1. DevTools Home (My DID + optional Other DID + recent)
  2. Collections list (search + pinned)
  3. Record list (infinite scroll + filter chip row)
  4. Record detail (collapsible JSON + copy/share)

Universal actions (every platform):
- Copy: AT URI, CID, rkey, collection NSID
- Export: JSON (share sheet on mobile, save-to-file on desktop)

================================================================================
DevTools - Storage (Drift)                                         *dev-storage*
================================================================================

Keep devtools cache-light (bounded, LRU):
  - store "recently viewed records" + "pinned collections" locally
  - cache record JSON for offline inspection (bounded by size + LRU)

Tables:
- dev_recent_records(
      uri TEXT PRIMARY KEY,
      did TEXT NOT NULL,
      collection TEXT NOT NULL,
      rkey TEXT NOT NULL,
      cid TEXT,
      viewedAt INTEGER NOT NULL,
      json TEXT,                 "bounded cache; null if too large"
      jsonSize INTEGER
  )
- dev_pins(
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      kind TEXT NOT NULL,        "collection|record"
      key TEXT NOT NULL,         "collection nsid OR record uri"
      createdAt INTEGER NOT NULL
  )
- dev_settings(
      id INTEGER PRIMARY KEY CHECK (id=1),
      enabled INTEGER NOT NULL,
      allowOtherRepos INTEGER NOT NULL,
      enableRecordEditing INTEGER NOT NULL,
      maxCachedJsonBytes INTEGER NOT NULL,
      showDebugFAB INTEGER NOT NULL
  )
- dev_network_logs(
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      method TEXT NOT NULL,
      url TEXT NOT NULL,
      statusCode INTEGER,
      durationMs INTEGER,
      requestBody TEXT,
      responseBody TEXT,
      timestamp INTEGER NOT NULL
  )

Indexes:
- dev_recent_records(did, viewedAt DESC)
- dev_recent_records(did, collection, viewedAt DESC)
- dev_network_logs(timestamp DESC)
- dev_network_logs(method, timestamp DESC)

Rationale:
- listRecords is already paged and cheap; caching is for "instant back" +
  offline peek.

================================================================================
DevTools - State + routing glue (Riverpod + go_router)              *dev-router*
================================================================================

Providers:
- Provider<DevtoolsRepository> (wraps XrpcClient + Drift DAOs)
- AsyncNotifierProvider
  <DevtoolsRepoController, RepoState> (describeRepo)
- AsyncNotifierProviderFamily
  <DevtoolsRecordsController, RecordsState, (did, collection, filter)>
- AsyncNotifierProviderFamily
  <DevtoolsRecordController, RecordState, (did, collection, rkey)>
- StateNotifierProvider
  <DebugOverlayController, DebugOverlayState> (internal debug mode only)
- AsyncNotifierProvider
  <NetworkInspectorNotifier, NetworkLogsState> (internal debug mode only)

Routes:
- /debug - Debug overlay home (system info + quick access) [kDebugMode only]
- /debug/network - Network inspector [kDebugMode only]
- /debug/performance - Performance metrics [kDebugMode only]
- /devtools - ATProto DevTools home [production, gated by Settings toggle]
- /devtools/:did/collections - Collections browser
- /devtools/:did/:collection - Records list
- /devtools/:did/:collection/:rkey - Record detail

Gating:
- Debug overlay (/debug/*) only rendered when kDebugMode == true
- DevTools routes (/devtools/*) gated by dev_settings.enabled toggle
- "Other DID" inspection requires allowOtherRepos == true
- Record editing requires enableRecordEditing == true + biometric auth

================================================================================
Implementation Notes                                                    *dev-imp*
================================================================================

For detailed task breakdown, see doc/roadmap.txt section M.5.

Key implementation patterns:

Debug Overlay (kDebugMode only):
- DebugOverlayHost wraps MaterialApp, only built when kDebugMode
- GestureDetector for 2-finger long-press (mobile) + KeyboardListener for ALT+F12
- DebugDrawer with tabs: System Info, ATProto Session, Network, Performance
- DebugNetworkInterceptor captures XRPC calls via Dio
- LRU eviction: 1000 logs in-memory, 24h in DB

User-Facing DevTools (production):
- Settings → "Developer Tools" toggle persists in dev_settings table
- DevToolsHomePage shows DID, PDS host, quick actions
- Collections browser with search, pinning, rich previews
- Records list with cursor pagination, filters
- Record inspector with JSON tree, syntax highlighting, copy buttons
- Write mode triple-gated: toggle + biometric + per-action confirmation

Security:
- Never log or display access tokens, refresh tokens, or DPoP keys
- Redact Authorization headers in network logs (show "Bearer ***")
- Defensive JSON rendering: limit depth to 50 levels, truncate long strings
- Write mode scoped to logged-in DID only (no editing other repos)
