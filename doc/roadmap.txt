DevTools - Scope & safety boundaries                                 *dev-scope*
================================================================================

Read-only by default (MVP):

- View your own repo (logged-in DID) + optionally view other public repos.

Hard rules:

- Never show or export auth secrets (tokens/DPoP keys) stored in secure storage.
- Default to "My DID". "Other DID" requires an explicit toggle and a
  confirmation.
- Record JSON rendering must be robust to hostile / weird shapes (defensive UI).

Host routing:

- These are PDS repo endpoints; call the user’s PDS directly:
  - describeRepo / listRecords / getRecord.
    (Do NOT use `atproto-proxy` here; that header is for proxying to other
    services, e.g. labelers/chat.)

================================================================================
DevTools - Data + endpoints (canonical)                                *dev-api*
================================================================================

Repo introspection:

- com.atproto.repo.describeRepo (GET) - lists collections for a repo.
  Query: repo=<did|handle>

Collection listing:

- com.atproto.repo.listRecords (GET) - list records in a collection.
  Query: repo=<did|handle>
         collection=<nsid>
         limit=<n>
         cursor=<cursor?>
         rkeyStart/rkeyEnd?
         reverse?

Single record:
- com.atproto.repo.getRecord (GET) - fetch record by repo+collection+rkey.
  Query: repo=<did|handle>
         collection=<nsid>
         rkey=<rkey>
         cid?<optional>

Advanced proof (optional later):
- com.atproto.sync.getRecord (GET) - "prove existence/non-existence" blocks.

Mutation:
- com.atproto.repo.createRecord (POST)
- com.atproto.repo.putRecord (POST)
- com.atproto.repo.deleteRecord (POST)
- com.atproto.repo.applyWrites (POST; batched transaction)

DevTools - Storage (Drift)                                         *dev-storage*
================================================================================

Keep devtools cache-light (bounded, LRU):
  - store “recently viewed records” + “pinned collections” locally
  - cache record JSON for offline inspection (bounded by size + LRU)

Tables:
- dev_recent_records(
      uri TEXT PRIMARY KEY,
      did TEXT NOT NULL,
      collection TEXT NOT NULL,
      rkey TEXT NOT NULL,
      cid TEXT,
      viewedAt INTEGER NOT NULL,
      json TEXT,                 "bounded cache; null if too large"
      jsonSize INTEGER
  )
- dev_pins(
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      kind TEXT NOT NULL,        "collection|record"
      key TEXT NOT NULL,         "collection nsid OR record uri"
      createdAt INTEGER NOT NULL
  )
- dev_settings(
      id INTEGER PRIMARY KEY CHECK (id=1),
      enabled INTEGER NOT NULL,
      allowOtherRepos INTEGER NOT NULL,
      maxCachedJsonBytes INTEGER NOT NULL
  )

Indexes:
- dev_recent_records(did, viewedAt DESC)
- dev_recent_records(did, collection, viewedAt DESC)

Rationale:
- listRecords is already paged and cheap; caching is for "instant back" +
  offline peek.

Manage records (write mode) - desktop-first, gated
--------------------------------------------------------------------------------

"Login to manage records in your repository"
It is intentionally gated because it can brick user data if sloppy.

Gate UX:
- Toggle: "Enable record editing (dangerous)"
- Require: biometric / device auth re-check (mobile) OR
           typed confirmation phrase (desktop)
- Scope: only logged-in DID (no editing other repos)

API tasks:
- [ ] Create: com.atproto.repo.createRecord (new rkey or server-generated).
- [ ] Update/Upsert: com.atproto.repo.putRecord.
- [ ] Delete: com.atproto.repo.deleteRecord.
- [ ] Batch ops (advanced): com.atproto.repo.applyWrites (transaction).

Screens:
- [ ] RecordEditorPage
  - JSON editor (text)
  - validate / format
  - dry-run diff preview (client-side)
- [ ] ApplyWritesReviewDialog (shows creates/updates/deletes summary)

Widgets:
- [ ] JsonCodeEditor (desktop: code editor-like; mobile: basic text editor)
- [ ] DiffViewer (desktop; minimal unified diff)
- [ ] DangerousActionButton (explicit styling + confirm step)

Tests:
- [ ] Contract tests against a test PDS (or recorded fixtures):
  - create → list shows new record
  - put → get shows updated record
  - delete → get fails / not found

  - cannot edit when gate is off

--------------------------------------------------------------------------------
Definition of Done
--------------------------------------------------------------------------------

Read-only explorer is "done" when:
- Dev mode toggles the entire feature set on/off.
- Collections are discovered via describeRepo.
- Records list is paged via listRecords with cursor.
- Record inspector loads via getRecord and exports/copies correctly.
- Desktop inspector + mobile drill-down both feel first-class (not "ported UI").

Write mode is "done" when:
- All mutation endpoints are wired with explicit gating and review UX.
- No accidental cross-repo editing is possible.
