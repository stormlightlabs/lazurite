Post Scheduling (Drafts -> Scheduled -> Posted)                     *bsky-sched*
================================================================================

Note: Part of Composer Parity Phase 4 (*bsky-A-p4*)
Status: Active - Ready for implementation

Design Principles:
- Ship quickly with testable architecture
- Swap schedulers later without refactoring
- Share posting logic across all modes
- Mobile OSes don't guarantee exact timing

User Stories:
- Schedule draft for future time
- View/cancel/reschedule upcoming posts
- See failures with clear reasons and retry
- Choose between notification-based or background auto-post

Non-Goals: Server-side scheduling (see *bsky-sched-backend*), enterprise job
orchestration, exact-time guarantees

Infrastructure                                                    *bsky-sched-1*
--------------------------------------------------------------------------------
Foundation: Database schema, domain models, repositories, posting worker

Tasks:
- [ ] Database migration: schedules table (draft_id, scheduled_at_utc, status,
      attempts, last_error, posted_uri/cid) with indexes
- [ ] Domain models: Schedule (draftId, scheduledAtUtc, status enum, attempts)
- [ ] ScheduleRepo: upsert, get, list, cancel operations
- [ ] PostPublisher service: publishDraft(draftId) with validation, session
      refresh, createRecord, status persistence
- [ ] Scheduler interface: schedule(), cancel(), resyncAll() for platform
      adapters
- [ ] Idempotency: prevent duplicate posts via posted_uri/cid checks

Tests:
- [ ] publishDraft builds correct ATProto record shapes
- [ ] Session refresh flow with token storage and retry
- [ ] State transitions: scheduled -> posting -> posted/failed
- [ ] Cancel prevents future publish
- [ ] Idempotency prevents duplicate posts

Definition of Done:
- All repository operations tested with Drift fakes
- PostPublisher unit tested with mock HTTP client
- State machine transitions validated
- Domain models use freezed for type safety
