H. Search and Feed Part 2 (hardening + completion)                      *bsky-H*
================================================================================

Context:
- Basic search and feeds are functional but have correctness issues and gaps.
- Feeds are prioritized over search improvements.
- Focus on data integrity, consistency, and UX polish.

Endpoints (already registered):
- app.bsky.feed.searchPosts (GET, requires auth)
- app.bsky.actor.searchActors (GET, registered but unused)
- app.bsky.feed.getFeed (GET)
- app.bsky.feed.getTimeline (GET)

Tasks:
- [x] Feed Data Integrity (CRITICAL):
      - [x] Fix home feed key collision risk:
            - replace 'home' literal with '__internal:home' prefix
            - add validation to prevent AT URI collisions
      - [x] Fix sortKey collision potential:
            - use microsecond precision instead of milliseconds
            - compound key: {timestamp}-{index}-{postUri}
      - [x] Add feed URI validation:
            - validate AT URI format before saveFeed()
            - reject malformed URIs with clear error message
      - [x] Fix optimistic update race condition:
            - wrap saveFeed/removeFeed in database transaction
            - ensure atomicity of local update + queue insert
- [x] Feed Sync Improvements (HIGH):
      - [x] Add sync queue retry limits:
            - add retryCount to PreferenceSyncQueue table
            - max 5 retries, then mark as permanently failed
            - cleanup failed items older than 30 days
      - [x] Add conflict resolution for multi-device sync:
            - timestamp-based merge strategy
            - preserve user intent (pins, order) on conflict
      - [x] Improve deprecated feed migration:
            - migrate users from _kDeprecatedDiscoverUri
            - preserve pin status and sortOrder
- [x] Feed UX Enhancements (MEDIUM):
      - [x] Feed reordering UI:
            - drag-to-reorder in FeedManagementScreen
            - update sortOrder on drag complete
            - sync to remote preferences
      - [x] Feed preview:
            - preview feed content before saving
            - show 10-20 posts in modal/sheet
            - "Save Feed" button from preview
      - [x] Feed discovery improvements:
            - search feeds by name/creator
            - category filters (if API supports)
- [x] Search Auth & Caching (HIGH):
      - [x] Fix search auth requirement mismatch:
            - We only want search for authenticated users
                  - handle unauthenticated users gracefully (i.e. hide from UI
                    for unauthenticated users)
      - [x] Implement recent search saving:
            - call saveRecentSearch() after successful query
            - wire up in SearchNotifier._search()
      - [x] Add search results caching:
            - cache SearchPostItems in database
            - similar to feed content caching strategy
            - 7-day retention policy
- [ ] Search Feature Completion (MEDIUM):
      - [ ] Add embed support to SearchPostItem:
            - include embed field in model
            - render images/videos in search results
            - reuse post embed widgets from feeds
      - [ ] Implement actor search:
            - use app.bsky.actor.searchActors endpoint
            - tab switcher: Posts / People
            - actor search results with follow button
      - [ ] Add search input debouncing:
            - 300ms debounce on text input
            - cancel in-flight requests on new input
- [ ] Architecture & Code Quality (MEDIUM):
      - [ ] Create unified post domain model:
            - consolidate SearchPostItem and FeedPost
            - shared Post model with adapters
            - reduce duplication in repository layer
      - [ ] Shared pagination utilities:
            - extract pagination logic to utility class
            - consistent cursor + hasMore pattern
            - reuse in search and feeds
      - [ ] Improve null safety:
            - typed models for API responses
            - safe navigation for nested JSON
            - reduce fragile metadata?['creator'] patterns
      - [ ] Profile deduplication:
            - profiles table as single source of truth
            - reference by DID across all features
      - [ ] Replace debugPrint calls with appropriately leveled logging calls

Tests:
- [ ] Feed key collision test: ensure '__internal:home' never collides
- [ ] sortKey uniqueness test: verify no duplicates on rapid pagination
- [ ] Sync queue retry test: verify max retries + cleanup
- [ ] Optimistic update transaction test: rollback on queue failure
- [x] Search auth test: unauthenticated user sees sign-in prompt
- [x] Recent search persistence test: verify saveRecentSearch() called
- [x] Search cache test: second query serves from cache
- [ ] Offline search test: cached results available offline
- [x] Feed sync conflict test: multi-device pin resolution
- [ ] Feed URI validation test: reject malformed URIs

Deliverables:
- [ ] Feeds are data-safe: no collisions, no race conditions
- [ ] Sync queue is bounded and self-cleaning
- [ ] Search works for unauthenticated users (with appropriate UX)
- [ ] Search results are cached for performance
- [ ] Feed reordering and preview improve discoverability
- [ ] Code quality: unified models, shared utilities

I. Profile + Thread Completion                                          *bsky-I*
================================================================================

Context:
- Current profile and post rendering handles basics but lacks critical features.
- Missing verification badges, content labels, viewer interaction states.
- Incomplete embed support (no external links, quoted posts).
- Profile and post data models need expansion for full AT Protocol surface.

Endpoints (already registered):
- app.bsky.actor.getProfile (GET)
- app.bsky.feed.getPostThread (GET)

Tasks:
- [ ] Profile Data Model & Display (HIGH):
      - [ ] Add profileViewDetailed fields to database:
            - pronouns, website, createdAt, verificationStatus
            - labels (JSON array), pinnedPostUri
      - [ ] Expand viewer relationship tracking:
            - viewerMuted, viewerBlocked, viewerBlockedBy
            - viewerFollowedBy, mutedByList, blockingByList
      - [ ] Profile UI enhancements:
            - verification badge display
            - pronouns next to display name
            - website as clickable link
            - account creation date
            - pinned post at top of profile feed
            - full viewer state indicators (muted/blocked states)
- [ ] Post/Thread Data Model (HIGH):
      - [ ] Add viewer interaction state to Posts table:
            - viewerLikeUri, viewerRepostUri
            - viewerBookmarked, viewerThreadMuted
            - quoteCount, bookmarkCount
      - [ ] Add content labels support:
            - labels column (JSON array)
            - parse and store from API responses
      - [ ] Create PostInteractions table:
            - normalized viewer state tracking
            - separate from post content
            - efficient querying of user engagement
- [ ] Embed Type Completion (MEDIUM):
      - [ ] External link embeds (app.bsky.embed.external#view):
            - link preview cards with title, description, thumbnail
            - clickable to open external URL
      - [ ] Record embeds (app.bsky.embed.record#view):
            - quoted posts as embedded cards
            - handle notFound/blocked states
            - support feed generators, lists, starter packs
      - [ ] Record with media embeds:
            - combine media above quoted post
            - support all media types
      - [ ] Improve existing embeds:
            - persist alt text for images
            - video duration and metadata
- [ ] Content Labels & Moderation (MEDIUM):
      - [ ] Label parsing and storage:
            - parse labels from posts and profiles
            - store label source (which labeler)
      - [ ] Label UI:
            - content warnings for labeled posts
            - blur/hide with click-to-reveal
            - display label types (spam, scam, etc.)
            - respect user moderation preferences
      - [ ] System labels:
            - handle ! prefixed behavioral labels
            - appropriate UI for directives vs descriptors
- [ ] Thread Structure (MEDIUM):
      - [ ] Complete thread navigation:
            - parent chain with configurable depth
            - reply tree with nesting
            - handle notFoundPost and blockedPost states
      - [ ] Thread context:
            - thread lines connecting related posts
            - highlight focal post
            - threadgate indicators for reply restrictions
- [ ] UI Components (MEDIUM):
      - [ ] New profile widgets:
            - VerificationBadge (icon + tooltip)
            - ProfileLabels (account label display)
            - PinnedPostCard (highlighted pinned post)
            - ProfileRelationshipIndicator (muted/blocked states)
      - [ ] New post widgets:
            - ExternalLinkCard (link preview renderer)
            - QuotedPostCard (embedded quoted posts)
            - ContentWarning (blur overlay for labels)
            - ThreadgateIndicator (reply restriction display)
            - VideoEmbed (video player with controls)
      - [ ] Update existing post cards:
            - reflect viewer interaction states in buttons
            - author verification badges
            - all embed types

Tests:
- [ ] Profile data persistence: verify all profileViewDetailed fields stored
- [ ] Verification badge display: verified accounts show badge
- [ ] Viewer state accuracy: follow/block/mute buttons reflect state
- [ ] External link embed: preview card renders correctly
- [ ] Quoted post embed: nested post displays properly
- [ ] Content label warning: labeled content shows blur/warning
- [ ] Thread parent chain: parent posts render in order
- [ ] Thread reply tree: replies nest correctly
- [ ] Viewer interaction state: like/repost state persists and displays
- [ ] Pinned post: appears at top of profile feed

Deliverables:
- [ ] All profileViewDetailed fields stored and displayed
- [ ] Verification badges on verified accounts
- [ ] Full viewer relationship state (follow/block/mute) working
- [ ] All embed types render (images, video, external, record, recordWithMedia)
- [ ] Content labels show warnings and respect preferences

L. DMs (read + write) + outbox + read-state                             *bsky-L*
================================================================================

DM fundamentals:
- Chat endpoints are called via user’s PDS and proxied to did:web:api.bsky.chat
  via service proxy header, per chat endpoint docs and XRPC proxy spec.

Endpoints:
- chat.bsky.convo.listConvos (GET)
- chat.bsky.convo.getMessages (GET)
- chat.bsky.convo.sendMessage (POST)
- chat.bsky.convo.acceptConvo (POST)
- chat.bsky.convo.updateRead (POST)

Tasks:
- [ ] Dio proxying:
      - add `atproto-proxy` header for all chat.* calls (service proxying).
- [ ] Drift tables:
      - dm_convos, dm_members, dm_messages
      - dm_outbox (local queued sends)
- [ ] Inbox UI:
      - convo list, unread indicators, accept requests flow
- [ ] Convo UI:
      - message list paging
      - compose/send
      - mark read on view (updateRead)
- [ ] Outbox worker:
      - persist pending messages immediately
      - retry sends safely (bounded; user-visible failure state)
      - never double-send without explicit server acknowledgement

Tests:
- [ ] Proxy header unit test: chat.* requests include atproto-proxy.
- [ ] Outbox tests: enqueue -> send -> mark delivered; retry on transient errors
- [ ] UI tests: offline send creates pending bubble; online later resolves.

Deliverables:
- DMs usable end-to-end: read, accept, send, read-state, robust retries.

N. Smart folders (local-only saved views)                               *bsky-N*
================================================================================

Definition:
- A smart folder is a saved query over cached posts + local metadata.
- It never fetches from network by itself; it organizes what’s already cached.

Tasks:
- [ ] Drift tables:
      - smart_folders (name, sortMode)
      - smart_folder_rules (type, payloadJson)
      - optional smart_folder_items materialization (later)
- [ ] Rule engine (MVP rule types):
      - author allow/deny (DIDs)
      - keyword include/exclude (text)
      - has media / has link
      - bookmarked only
      - exclude replies / replies only
- [ ] UI:
      - create/edit folder
      - folder list and folder detail view

Tests:
- [ ] Rule evaluation tests against fixture posts.
- [ ] Query performance test with N=10k cached posts.

Deliverables:
- "Saved views" that feel like feeds, entirely local and fast.
